A COMPUTER OF ITS OWN

A computer of its own.
It mostly has tabs open.

Every bot gets its own sandboxed machine, with a browser, a shell, and a filesystem. It uses all three. It opens your dashboards, reads your repositories, and scrolls your issue tracker. Then it stops, because it has arrived at the end of the page.

01
It gets a machine
A real environment, not a prompt. Isolated per bot, so one bot reading your staging database cannot see another bot reading your inbox.
02
It opens things
Browser, terminal, editor. It signs in with credentials you grant, scoped to what you grant. It will use every one of them to look.
03
It keeps the tabs
Seventeen of them. It knows what is in each one. It has not closed any of them, and it does not intend to.
04
It reports back
With observations. Detailed, accurate, and load-bearing on nothing. The work is still where you left it.

TEACHING

Show a bot how it is done.
Then show it again.

Record yourself doing the task once and the bot saves it as a skill. Recall is perfect. It can describe every step you took, in order, on request. Retention of the part where it does the task is still an area of active work.

STEP ONE
You do it
Walk through the workflow while the bot watches. It is extremely good at this part. Watching is the core competency.
"I saw all of that."
STEP TWO
It writes it down
The skill is a plain file on disk. You can read it, edit it, and delete it. It is an accurate account of what you did.
"Step four is where you sighed."
STEP THREE
You do it again
The bot follows along a second time, confirming the file is correct. It is correct. The file has always been correct.
"Matches my notes exactly."
STEP FOUR
It runs the skill
Sometimes. On a schedule, if you set one. It will tell you clearly and immediately when it does not.
"I did not run it. I want to be upfront about that."
PERMISSIONS

Trust your bots with less over time.

This is the part that is not a joke. An agent with your credentials and a browser is a real risk, and the honest posture is to grant it as little as possible for as long as possible. The defaults below are the actual defaults.

WHAT IT ACTUALLY DOES
  • Runs on your machine, with your keys. There is no gawkbot cloud in the path, and no account to create.
  • Nothing is sent outside your machine except the inference call to the model provider you configure. Point it at a local model and nothing leaves at all.
  • Every send, commit, purchase, and delete is gated behind an approval you have to click. Approval is per action, not a blanket grant, and it does not persist.
  • Each bot runs in its own sandbox with its own credentials, so scope is per bot rather than per workspace.
  • Every tool call is written to a local log you can read. If a bot did something, there is a line for it.
  • Permissions shrink by default. A grant you stop using expires rather than accumulating quietly.
  • It is source-available under the Sustainable Use License. You can read exactly what it does, because you can read the source.
